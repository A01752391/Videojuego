# PAWNED - Proyecto de Base de Datos Relacional

Para el desarrollo de esta tarea se realizó una base de datos relacional en MySQL para el proyecto **PAWNED**. Concretamente, se construyó un sistema de gestión de partidas multijugador de ajedrez con power-ups.

## 🔧 Justificación de Llaves Primarias y Foráneas

### Llaves Primarias

Cada tabla contiene una llave primaria (`PRIMARY KEY`) única que identifica de forma inequívoca cada fila:

- `Jugador(id_jugador)`: Identificador único del jugador.
- `Partida(id_partida)`: Identificador único de cada partida.
- `Ronda(id_ronda)`: Identificador único de cada ronda dentro de una partida.
- `Pieza(id_pieza)`: Identificador único de cada pieza en una partida.
- `Powerup(id_powerup)`: Identificador del tipo de power-up.
- `Powerup_usado(id_uso)`: Identificador del uso individual de un power-up.
- `Estadistica_partida(id_estadisticapartida)`: Identificador de estadísticas por partida.
- `Estadistica_ronda(id_estadisticaronda)`: Identificador de estadísticas por ronda.
- `Turno(id_movimiento)`: Movimiento individual dentro de la partida.
- `Jugador_Partida(id_jugador, id_partida)`: Composición para representar la participación del jugador en una partida (llave compuesta).

### Llaves Foráneas

Las llaves foráneas (`FOREIGN KEY`) se utilizan para asegurar la integridad referencial entre las tablas:

- `Partida.id_jugador1` y `id_jugador2` → `Jugador.id_jugador`
- `Partida.ganador_id` → `Jugador.id_jugador`
- `Pieza.id_partida` → `Partida.id_partida`
- `Pieza.id_jugador` → `Jugador.id_jugador`
- `Powerup_usado.id_jugador` → `Jugador.id_jugador`
- `Powerup_usado.id_powerup` → `Powerup.id_powerup`
- `Powerup_usado.id_partida` → `Partida.id_partida`
- `Powerup_usado.id_ronda` → `Ronda.id_ronda`
- `Ronda.id_partida` → `Partida.id_partida`
- `Ronda.ganador_id` → `Jugador.id_jugador`
- `Turno.id_partida` → `Partida.id_partida`
- `Turno.id_pieza` → `Pieza.id_pieza`
- `Estadistica_partida.id_partida` → `Partida.id_partida`
- `Estadistica_partida.id_jugador` → `Jugador.id_jugador`
- `Estadistica_ronda.id_ronda` → `Ronda.id_ronda`
- `Estadistica_ronda.id_jugador` → `Jugador.id_jugador`
- `Jugador_Partida.id_jugador` → `Jugador.id_jugador`
- `Jugador_Partida.id_partida` → `Partida.id_partida`

Estas relaciones modelan adecuadamente el flujo de una partida, el uso de power-ups y las estadísticas de juego por jugador y ronda.

## 🧠 Forma Normal (Resumen)

El diseño de la base de datos cumple con la **Tercera Forma Normal (3FN)**:

- 1FN: Todos los atributos contienen valores atómicos y no repetitivos.
- 2FN: Todas las tablas con llaves compuestas tienen atributos totalmente dependientes de la llave completa.
- 3FN: No existen dependencias transitivas entre atributos no clave.

Para más detalles, consultar el documento `Justificación de la normalización.pdf`
